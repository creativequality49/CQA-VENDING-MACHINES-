# CQA Digital Vending Machines

Creative Quality Australia production SaaS for AI vending-machine storefronts, secure vault delivery, content drops, Stripe entitlements, Supabase/Postgres data, and private Supabase Storage downloads.

## Live app surfaces

- `/store` — customer-facing product store backed by the `products` and `machines` tables.
- `/vault` — entitlement-aware customer vault with locked states and signed download links only after server-side access checks.
- `/scarlett` — Scarlett May sales funnel backed by real Scarlett machine product records.
- `/admin` — admin command centre with live database counts and links to content/product operations.

## Data model

The Prisma schema and migration create these production tables:

- `machines`
- `products`
- `content_items`
- `content_drops`
- `content_drop_items`
- `customer_entitlements`
- `download_logs`
- `content_bundles`
- `bundle_items`
- `email_logs`
- `content_analytics`

Legacy compatibility tables are also retained for users, profiles, orders, subscriptions, Stripe event idempotency, support tickets, analytics events, and vault access.

## Stripe

- Checkout starts at `/api/stripe/checkout` and requires products to have `stripe_price_id`.
- Webhooks are handled at `/api/stripe/webhook` with raw `req.text()` signature verification.
- Processed event IDs are stored in `stripe_events` for idempotency.
- Successful checkouts create `orders` and `customer_entitlements`.
- Subscription created/updated/deleted events activate or deactivate subscription entitlements.

## Vault and downloads

- `/vault` never shows paid download buttons unless the customer has a valid entitlement.
- Free published content can appear to customers.
- Admin-only, draft, rejected, archived, scheduled, unreleased, and expired content is not downloadable by customers.
- `/api/content/[id]/download` verifies authentication, content status, entitlement, and then creates a short-lived signed Supabase Storage URL.
- Paid/private file paths are stored in the database; public file URLs are not exposed.

## Scheduled drops

`POST /api/cron/publish-scheduled-content?secret=$CRON_SECRET` publishes scheduled content and drops idempotently, updates included content items, and queues one email log per drop.

## Supabase setup

1. Apply the Prisma migration or run `npm run db:push` against Supabase Postgres.
2. Run `supabase-policies.sql` for starter RLS policies.
3. Create the private Storage bucket named by `SUPABASE_STORAGE_BUCKET`.
4. Keep `SUPABASE_SERVICE_ROLE_KEY` server-side only.

## Operations backbone

This build includes an operations-aware commerce layer:

- Stripe webhooks create idempotent orders and order items; success pages never grant access.
- Product types supported: `DIGITAL`, `PHYSICAL`, `SUBSCRIPTION`, and `BUNDLE`.
- Digital products create `digital_access` records and customer entitlements.
- Physical products create `fulfillment_tasks` and inventory movement logs.
- Bundle products expand through `bundle_components` for internal fulfillment/access routing.
- Admin operations pages: `/admin/orders`, `/admin/products`, `/admin/inventory`, `/admin/fulfillment`, `/admin/subscriptions`, `/admin/customers`, `/admin/reports`, `/admin/reports/top-products`, `/admin/settings`.
- Customer account pages: `/account`, `/account/orders`, `/account/downloads`, `/account/subscriptions`, `/account/support`.
- Audit logs and notifications are generated by reusable service functions in `services/`.
- Optional courier/shipping provider keys can be wired into `services/fulfillment.service.ts` for live label purchasing.
